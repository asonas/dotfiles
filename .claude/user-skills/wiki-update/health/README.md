# wiki 健康診断

`/wiki-update` が育てている `wiki/` そのものの状態を測る道具です。**検索品質は測りません**（そちらは `vault-rag/bench/` の担当）。この2つは別の問いに答えます。

- `vault-rag/bench` — 「聞いたことが引けるか」
- `wiki-update/health` — 「wiki が積もっているか」

## wiki-health.rb

```sh
ruby wiki-health.rb          # 人が読む形式
ruby wiki-health.rb --json   # 記録・比較用
```

週次 lint のたびに実行し、結果を `wiki/log.md` の lint エントリの `health:` 行に残します。

見るべき指標は2つです。

**`pages_touched_per_ingest`** — 1回の ingest で作成・更新したページ数。スキルの想定は 10〜15。ここが低いと wiki は「積もる場所」ではなく「一度書いて放置される場所」になります。

**`deferred` の残件数** — ページ化待ちが増え続けているなら、ingest 手順 6 の回収が実行されていません。減っているなら回っています。

## mentions.rb

ingest のエンティティ抽出を機械的に補助します。LLM の一発読みは取りこぼすので、その下限を機械で押し上げるためのものです。

```sh
ruby mentions.rb daily/2026-07-25.md activities/2026-07-25.md
ruby mentions.rb --candidates daily/2026-07-25.md
```

- 引数なしモード: ソースに言及されている**既存の** wiki ページを `linked`（既に `[[]]` 済み）/ `plain`（リンクなしで言及）/ `alias`（別名で言及）に分けて出す。増補すべきページの候補
- `--candidates`: 既存ページでも deferred 台帳にも無い語を列挙する。**新規ページ候補のチェックリスト**

`--candidates` はノイズを含みます。一般的なカタカナ語と Linear の issue ID（vault では意図的に赤リンクのまま運用）は除外していますが、それでも1日分で 40〜50 語出ます。ページ化の判断は必ず本文を読んで行い、2ソース・ルールにかけてください。

このスクリプトは**下限であって上限ではありません**。自分の読みで拾った語がスクリプトに出てこないこともあるので、その場合は自分の読みを優先します。

## verify-sources.rb

`sources:` に書かれた出典が、本当にそのページの主題に触れているかを検証します。

```sh
ruby verify-sources.rb                 # 全ページ
ruby verify-sources.rb Linear TDD      # ページ名を指定
ruby verify-sources.rb --quiet         # NG のみ
```

**`wiki-health.rb` は `sources` が空かどうかしか見ません。** 自信を持って書かれた誤った出典は、正しい出典と同じスコアになります。この差を埋めるのが verify-sources.rb です。

事故は deferred の回収で起きやすいという性質があります。回収対象の語は「特定のノートを読んで書く」のではなく「vault 全体を grep して材料を集めて書く」ことになるためで、このとき `grep -rh` のようにファイル名が落ちる形で調べると、文は手元にあるのに出典が分からないまま frontmatter を書いてしまいます。2026-07-26 の ingest では実際に 6 ページで誤った出典が入り、事後に修正しました。**材料集めには `grep -rn` か `grep -rl` を使うこと。**

出力の NG は「要確認」であって「誤り確定」ではありません。表記が違うだけの正当なケース（`Datadog` に対する `datadoghq`）は aliases への追記で解消します。

出典を実際に読んで「正しいがページ名が本文に現れないだけ」と判断した組は `verify-sources-accepted.tsv` に理由つきで記録すると、次回から抑止されます。`--show-accepted` を付ければ抑止した組も表示できます。**aliases を歪めて黙らせるのではなくこちらを使ってください。** 別名でないものを aliases に足すと、`mentions.rb` の言及検出が誤爆するようになります。

### 2026-07-26 の全件監査

初回の全件監査で **37 ページ → 6 ページ**まで減らしました。分かったことが2つあります。

**出典の誤りは wiki の初期から入っていました。** 2026-07-26 の ingest 特有の事故ではありません。最も多いパターンは「作業した日付の daily を出典に書くが、内容の実体は別リポジトリの doc にある」というもので、daily が薄く実作業の記録がプロジェクト側にある案件（ai-cost-management など）で起きます。

**frontmatter と本文で出典が食い違うことがあります。** `sources` には正しい外部 doc が載っているのに、本文の段落末尾の引用だけ daily を指している例が [[ai-cost-management]] で 4 箇所ありました。frontmatter が埋まっているだけでは不十分です。

未解決として残った 6 ページは、**wiki 層にしか存在しない記述**を含みます（`Daisy Seed` の製品仕様、`Workload Identity Federation` の `client_assertion` の詳細など）。外部の design-doc や Notion が出典なら vault の慣習どおり文字列で書けば済みますが、そうでなければ記述ごと落とす必要があります。判断には本人の知識が要るため保留しています。
